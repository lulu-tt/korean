## 0. 한눈에

```
[원자료 엑셀 44개]                      제보자 1명 = 파일 1개
      │  관리자 › 지역어 기상도 › 업로드 (사전 점검 → 적재)
      ▼
[DB] wb_weather_file · wb_weather_response · wb_weather_adjust
      │  판정 (build_output) — 규칙은 한 곳에서만
      ▼
[결과 JSON] 항목 101개 × 지역 9곳 × (상태·점수·제보자 사례·세대·성별)
      │                                   │
      ▼                                   ▼
 관리자 항목 목록 / 응답 관리          사용자 화면 dialect_gisangdo.html (지도)
```

- 원자료를 DB에 올리면 판정은 **서버가 매번 같은 함수로** 다시 계산한다. 정적 JSON 을 따로 굽지 않는다.
- 판정 규칙은 **한 곳**에만 둔다. 관리자 화면·사용자 화면·배포본이 서로 다른 규칙을 쓰면 숫자가 어긋난다. 실제로 그런 사고가 있었다.
- DB 원본은 **고치지 않는다**. 사람이 판단을 바꿔야 할 때는 '보정' 표(§6)에만 적는다.

## 1. 용어

| 용어 | 뜻 |
|---|---|
| 항목번호 | 5자리 단어 번호. 예: `21105` = 호미 |
| 하위코드 | `21105-A-1`처럼 항목번호 뒤에 붙는 번호. "이것도 아세요?" 하고 **변이형을 제시해서 물은 줄**이다 |
| 표제어 | 그 줄에서 제보자에게 **물은 말**. 하위코드가 없는 줄은 표준어(예: 호미)를, 하위코드가 있는 줄은 제시한 변이형(예: 호맹이)을 물은 것이다. 원자료 칸 이름은 '표준어형'·'표제어' 등으로 흔들린다 |
| 방언형(기저형) | 제보자가 **실제로 구술한 말**. 비었거나 `*` 이면 말하지 않은 것이다 |
| 사용도/인지도 (등급) | 그 줄의 말에 대한 제보자의 응답. 1 지금도 씀 · 2 써 봤으나 안 씀 · 3 들어 봄 · 4 처음 들음 |
| 제보자 | 파일 하나 = 사람 하나. 파일명 앞 9자리(`CB2570FVE`)가 식별자다 |
| 연차(research_degree) | 조사 사업 회차. 파일명의 두 자리 연도(`25`). 지금 데이터는 모두 25 |
| 대표 표제어 | 한 항목(하위코드 줄 포함)에서 가장 많이 적힌 표제어. 지도의 단어 이름으로 쓴다 |
| 지역어형 | 표제어(표준어)와 다른 말. 판정에는 **지역어형에 붙은 등급만** 쓴다 |

> 화면 문구에서는 '표준어형' 대신 **'표제어'**를 쓴다 (2026-10-08 결정).

## 2. 원자료 서식 (2025, 새 서식 V6)

### 2.1 파일

- **파일명**: `{지역2}{연차2}{세대2}{성별1}VE_사용도인지도.xlsx`. 예: `CB2570FVE_사용도인지도.xlsx` = 충북 · 25년 · 70대 · 여.
  - 지역: GG 경기 · GW 강원 · CB 충북 · CN 충남 · JB 전북 · JN 전남 · GB 경북 · GN 경남 · JJ 제주
  - 세대: 20 · 50 · 70 / 성별: F 여 · M 남
  - 식별 열쇠는 앞 9자리다(`CB2570FVE`). 꼬리(`_사용도인지도`)는 없어도, 달라도 같은 사람이다.
- **설계상** 지역마다 6명(3세대 × 남녀), 모두 54명이다. **지금 받은 것은 44명**이다(§11).
- **첫 시트만** 정본이다. 다른 시트는 읽지 않는다. 값이 남아 있으면 경고만 한다.

### 2.2 열 (머리글 1행)

| 열 | 머리글 | 비고 |
|---|---|---|
| A | 제보자 | 파일명 앞 9자리와 같아야 한다. 다르면 **파일째 거부** |
| B | 일련번호 | `제보자 + 항목번호`(예: `CB2570FVE21105-A-1`). 판정에는 안 쓴다 |
| C | 항목번호 | `21105` 또는 `21105-A-1` |
| D | 표준어형 / 표제어 | 머리글 이름이 흔들린다. 별칭으로 모두 받는다(§2.4) |
| E | 방언형(기저형) | 비거나 `*` = 말하지 않음 |
| F | 사용도/인지도 | 1~4. 전각 숫자(`１`)는 반각으로 맞춘다 |

### 2.3 데이터 정리 방침 (담당자와 합의된 것)

1. **등급이 없는 줄은 원자료에서 뺀다.** 담당자가 일부러 제외한 것이다. "사라진 줄"로 취급하지 않는다.
2. 한 제시어의 **구술 변이를 하위코드로 나눠 적는 것은 정상**이다. 같은 제시어 '벌기'가 방언형만 달리 두 줄인 것도 정상이다.
3. 한 제보자 안에서 **서로 다른 제시어가 같은 하위코드를 쓰면** 뒤 줄을 다음 빈 번호로 옮긴다. 예: `20610-A-1` → `-A-2`.
4. **괄호 주석은 붙이는 쪽으로 통일**했다: 회충(蛔蟲) · 가(邊) · 새끼(繩) · 키(箕) · 할머니(호칭) · 형(호칭) · 사위(호칭).
5. 여러 표준어를 함께 적을 때는 `서 되/세 되`, `다르다/틀리다`처럼 `/`로 잇는다.
   - 예외로 '서 되'와 '틀리다'를 각각 따로 물은 줄은 그대로 둔다.
6. 빠진 제보자 3명(CB2570MVE · GW2570FVE · JN2550MVE)과 GG2520FVE의 20718(사위) 줄은 **자료 없음**으로 처리한다.

### 2.4 읽을 때 반드시 처리할 함정

| 함정 | 증상 | 처리 |
|---|---|---|
| 머리글 이름 흔들림 | '표준어형(수정)', '인지도/사용도' 등 | 공백 제거, 꼬리 `(수정)·(보충)·(최종)·(검수)` 제거 후 별칭 표로 모은다. `표제어·표제어형·표준어형·대응표준어` → 표제어, `인지도/사용도` → 사용도/인지도 |
| 엑셀 **수식 칸** | 일련번호가 `=A2&C2`, 일부 파일은 항목번호가 `=SUBSTITUTE(B2,…)` | **결과값(cached value)으로 읽는다.** 수식을 다시 계산하지 않는 라이브러리로 저장하면 값이 사라지니 주의한다 |
| 한글 파일명 NFD | macOS가 준 파일명이 자모 분리형이라 비교·엑셀 표기가 깨진다 | 비교하기 전에 NFC로 정규화한다 |
| 엑셀 잠금 파일 | 폴더에 `~$…xlsx`가 섞여 있다 | 건너뛴다 |
| 빈 줄 | 시트 중간에 빈 행이 있다 | 건너뛴다. 단 **행 번호를 사람에게 알릴 때는 실제 엑셀 행 번호**를 써야 한다 |
| 첫 시트 ≠ 활성 시트 | active 시트를 읽으면 다른 시트를 읽는다 | 항상 첫 시트(index 0) |

참고 구현: `neibis-cms/serve.py` `_wb_norm_header` · `_wb_parse_filename` · `_wb_file_key` · `_wb_read_sheet`

## 3. DB 스키마

### 3.1 원본 3표 (로컬 SQLite `data/gisangdo.db` · 배포 Turso `korean-dialect`)

```sql
-- 제보자 파일 (1행 = 1명)
CREATE TABLE wb_weather_file (
  weather_file_id INTEGER PRIMARY KEY,
  file_nm TEXT NOT NULL UNIQUE,      -- 제보자 열쇠 'CB2570FVE.xlsx' (파일 원래 이름이 아님)
  region_cd TEXT NOT NULL, region_nm TEXT,
  research_year INTEGER,             -- 2025
  research_degree TEXT,              -- '25'  ← 연차 필터는 이 값
  generation INTEGER, sex TEXT,      -- 20/50/70, 'F'/'M'
  row_cnt INTEGER DEFAULT 0, item_cnt INTEGER DEFAULT 0,
  src_layout TEXT,                   -- 'V6'(새 서식) / 'V5' / 'RAW'
  use_yn TEXT DEFAULT 'Y', reg_id TEXT, reg_dt TEXT, upt_id TEXT, upt_dt TEXT);

-- 응답 (1행 = 엑셀 1줄)
CREATE TABLE wb_weather_response (
  response_id INTEGER PRIMARY KEY,
  weather_file_id INTEGER NOT NULL REFERENCES wb_weather_file,
  line_no INTEGER NOT NULL,          -- 빈 줄을 뺀 순번
  serial_no TEXT, item_cd TEXT NOT NULL,
  item_base TEXT,                    -- 항목번호 앞 5자리. 판정은 이 값으로 묶는다
  headword TEXT,                     -- 표제어(물은 말)
  dialect_form TEXT,                 -- 방언형(기저형)
  grade TEXT,                        -- 원문 그대로
  grade_valid_yn TEXT DEFAULT 'N',   -- grade ∈ {1,2,3,4} 이면 'Y'
  use_yn TEXT DEFAULT 'Y', reg_dt TEXT, upt_dt TEXT);

-- 담당자 보정 (§6). 원본을 고치지 않고 여기에만 적는다
CREATE TABLE wb_weather_adjust (
  file_nm   TEXT NOT NULL,           -- 제보자 열쇠
  item_base TEXT NOT NULL,           -- 항목 5자리
  grade     TEXT NOT NULL,           -- '1'~'4' 또는 'X'(이 제보자를 이 항목 판정에서 뺀다)
  src_sig   TEXT,                    -- 보정할 때 본 응답 지문 'dialect_form/grade|…'
  reg_dt TEXT, upt_dt TEXT,
  PRIMARY KEY (file_nm, item_base));
```

## 4. 업로드 (관리자)

### 4.1 사전 점검 (브라우저, 올리기 전)

| 결과 | 조건 |
|---|---|
| 중단 | 파일명이 규약과 다름 |
| 중단 | 9개 지역이 아닌 지역코드 |
| 중단 | 이미 **보정이 달린** 제보자 파일을 덮어쓰려 함 (보정을 먼저 확인하게) |
| 경고 | 엑셀 잠금 파일(`~$`)은 제외함 |
| 경고 | 같은 제보자 파일이 둘 이상 (뒤엣것은 안 올림) |
| 경고 | 이미 올라가 있는 제보자 (덮어씀) |
| 경고 | 적재해도 자료가 없는 지역이 있음 → 그 지역은 지도에서 **관측 없음** |

### 4.2 서버 적재 (파일마다)

| 결과 | 조건 |
|---|---|
| 거부 | 파일명 규약 불일치 · 지역코드 이상 · 엑셀 읽기 실패 · 항목번호 있는 행이 없음 |
| 거부 | **제보자 칸 ≠ 파일명 앞 9자리** (다른 사람 응답이 섞이는 것을 막음) |
| 경고(받음) | 표제어 칸에 하위코드가 섞임 (`반짇그릇-A-1`) |
| 경고(받음) | 항목번호가 **서비스 목록(§5.1)에 없음** — 대개 번호 오타. 지도에 안 나온다 |
| 경고(받음) | 첫 시트 말고 다른 시트에 값이 남아 있음 |
| 집계 | 등급이 1~4가 아닌 줄 수(빈칸·`*` 제외) |

- 같은 제보자는 **재업로드**로 본다. 파일명이 아니라 제보자 열쇠로 찾아 기존 행을 지우고 다시 넣는다.
- 항목번호가 빈 줄은 버린다(`dropped`).
- 보정 표는 건드리지 않는다. 보정은 제보자·항목 열쇠라서 재업로드해도 살아남는다. (파일 **삭제**는 보정도 지운다 — §8.1)
- 서식 판별: 머리글에 '제보자'가 있으면 `V6`(2025 새 서식), 아니면 열이 6개 이하일 때 `V5`, 그 밖은 `RAW`(조사 원본)다.
  - 2022~2024 옛 서식도 별칭으로 읽기는 한다. 하지만 §2.3 정리 방침(등급 없는 줄 제외 등)은 **2025 새 서식에만** 적용돼 있다.
  - 옛 연차 자료를 '전체'에 섞으려면 같은 방침으로 먼저 정리해야 한다. 정리하지 않으면 등급 없는 줄이 남아 '관측 없음' 칸이 늘어난다.

참고 구현: `api_weather_upload` (`neibis-cms/serve.py`), 사전 점검은 `weather.html`의 업로드 탭

## 5. 판정 규칙 ★ 가장 중요

참고 구현: `scripts/etl_awareness_region.py` `build_output()`. 관리자·사용자·배포본이 모두 이 함수 하나를 부른다.

### 5.1 서비스 대상 항목

- `scripts/gisangdo_service_items.json`에 적힌 **101개 항목번호** 가운데, 어느 지역에서든 등급이 하나라도 관측된 항목만 대상이다.
- 2026-10 이전에는 "9개 지역이 모두 조사된 항목"이 기준이었다. 이 기준을 **버렸다**.
  - 한 지역에 자료가 없으면 항목이 통째로 빠졌다. 2025 자료에서 제주 5항목이 이렇게 빠졌다.
- 자료가 없는 지역은 항목을 빼지 않고 **관측 없음**으로 남긴다.
- 목록 파일이 없을 때만 예전 기준으로 돌아간다. 어느 기준을 썼는지는 `meta.itemFilter`(`list` / `all-regions`)로 알린다.
- **항목을 더하거나 뺄 때**는 다음 순서로 한다.
  1. `gisangdo_service_items.json`의 `items`에 `{code, standard}`를 고친다.
  2. 사용자 화면의 범주표(`dialect_gisangdo.html`의 `CATEGORY`, 항목번호 앞 3자리 → 범주)에 해당 범주가 있는지 확인한다. 없으면 '기타'로 묶인다.
  3. 배포하고, Turso 동기화로 미리 계산을 다시 만든다.
- 사용자 화면의 단어 차례는 화면 안 큐레이션 표(처음 101개의 순서·범주)를 따른다. 표에 없는 새 단어는 항목번호 앞 3자리로 범주를 정해 뒤에 붙인다.

### 5.2 한 줄을 어떻게 보나

```
form   = 방언형이 있고 '*'가 아니면 방언형, 아니면 표제어
지역어형 = form 을 정규화(괄호 안·공백·콜론 제거)한 값이
          대표 표제어를 '/' 로 쪼개 정규화한 집합에 들어 있지 않음
          예) 대표 표제어 '서 되/세 되' → {서되, 세되}, '할머니(호칭)' → {할머니}
등급    = grade 가 1~4 (전각은 반각으로). 그 밖(빈칸·'*'·'1,4')은 등급 없음
```

- **대표 표제어** = 그 항목(앞 5자리가 같은 줄 전부, 하위코드 줄 포함)에서 가장 많이 적힌 표제어. 표준어를 묻는 줄이 제보자마다 있어서 보통 표준어가 뽑힌다. 지도의 단어 이름이기도 하다.
- 화면에 보이는 단어 이름(`word`)은 대표 표제어에 별칭 표 `WORD_ALIAS`(ETL)를 한 번 더 적용한 값이다. 예: `가` → `가(邊)`, `아우 타다` → `아우타다`.
  - 2026-10-08 주석 통일 뒤 20322는 '회충(蛔蟲)'으로 나온다.

### 5.3 제보자 → 지역

1. **제보자 대표 등급**: 그 제보자의 지역어형 줄 가운데 **가장 작은 등급**(가장 살아 있는 쪽)을 쓴다. 동률이면 어형 가나다순.
   - 보정이 있으면 보정값을 쓴다(§6). `X`면 이 항목 판정에서 그 제보자를 뺀다.
2. **점수**: 등급 1=100 · 2=75 · 3=50 · 4=25. **지역 점수 = 제보자 대표 등급 점수의 평균**(소수 둘째 자리).
   - 평균은 지역의 전체 인원이 아니라 **그 항목에서 대표 등급이 있는 제보자만으로** 낸다. 이 인원이 결과의 `n`이다.
   - 대표 등급이 없어 평균에서 빠지는 사람은 두 경우다.
     - 그 항목에 표제어(표준어)로만 답한 사람: 지역어형이 없다.
     - 지역어형 줄은 있는데 등급이 비어 있는 사람.
   - 그래서 같은 지역이라도 항목마다 `n`이 다를 수 있다.
   - `n = 0`이면 평균을 내지 않는다. 모두 표제어로만 답했으면 `std`, 그 밖이면 `w0`이다.
3. **상태** (경계는 등급 사이 중간값이라 임의값이 아니다)

| 상태 | 조건 | 사용자 화면 라벨 |
|---|---|---|
| `w1` | 점수 ≥ 87.5 | 맑음 — 대체로 지금도 씀 |
| `w2` | 62.5 ≤ 점수 < 87.5 | 구름조금 — 쓰거나 써 본 사람이 많음 |
| `w3` | 37.5 ≤ 점수 < 62.5 | 흐리고 비 — 들어는 본 정도가 많음 |
| `w4` | 점수 < 37.5 | 천둥번개 — 대체로 처음 들음 |
| `std` | 그 지역에 줄은 있는데 **지역어형이 하나도 없음** | 지역어형 없음 — 결측이 아니라 조사 결과 |
| `w0` | 줄이 없거나, 지역어형은 있는데 등급이 없음 | 관측 없음 |

4. **세대 칸·세대×성별 칸**도 같은 식(점수 평균 → 구간)으로 만든다. 세대 칸만 다른 식을 쓰면 범례와 어긋난다.
5. **전체(통합) 지도**: 101개 항목 전부에서 (제보자, 항목)마다 대표 등급 하나씩을 모아 같은 식에 넣는다.

## 6. 보정 (담당자 판단)

- 판정 결과가 자료와 맞지 않을 때 담당자가 **제보자 × 항목** 단위로 대표 등급을 바꾼다.
  - 값은 `1~4`, 또는 `X`(그 제보자를 이 항목에서 뺌)다. 빈 값으로 저장하면 보정이 해제된다.
- 원본 응답은 그대로 두고 `wb_weather_adjust`에만 저장한다. 재업로드해도 보정은 살아남지만, 파일을 삭제하면 그 제보자의 보정도 함께 지워진다.
- 보정할 때 본 응답 지문(`src_sig`)을 함께 저장한다. 원본이 바뀌어 지문이 달라지면 화면에서 "확인 필요"로 알릴 수 있다.
- 보정 사유 칸은 두지 않기로 했다.
- 업로드 목록의 `✎N`은 그 제보자에게 걸린 보정 항목 수다.
- **현재 보정은 0건이다.** 2026-09에 시험으로 넣은 1건이 남아 있었는데, 2026-10-12에 해제했다.
  - 시험값은 실제 DB에 남기지 않는다.

## 7. 연차

- 연차는 `research_degree`(예: `'25'`)로 거른다. 연도 숫자가 아니라 사업 회차다.
- `year=latest`는 서버가 `MAX(research_degree)`로 풀어 준다. 그래서 화면이 연차 목록을 따로 부르지 않아도 된다.
- `year=` 빈 값은 전체 누적이다.

### 7.1 '전체'는 어떻게 계산하나

'전체'는 연차별 지도를 더하거나 평균하지 않는다. **모든 연차의 응답을 한꺼번에 읽어 §5 판정을 처음부터 다시 한다.**

- 지역 점수는 모든 연차 제보자의 대표 등급 점수를 평균한 값이다. 제보자가 많은 연차가 결과에 더 크게 반영된다(인원 가중).
- **같은 사람이 두 연차에 모두 조사됐어도 두 명으로 센다.** 파일명에 연차가 들어가 다른 제보자로 잡힌다(`CB2470F` ≠ `CB2570F`).
- 서비스 목록(§5.1)은 합친 자료에 똑같이 적용한다.
- 보정(§6)은 연차가 들어간 파일명이 기준이라 연차별로 따로 걸린다.
- 배포본은 동기화할 때 `awareness`(전체)와 `awareness:NN`(연차별)을 따로 미리 계산해 둔다.

시험 예시(2026-10-12): 사본 DB에서 충북 제보자 5명 전원(CB2570MVE는 원래 없음)을 24년차로 복제했다. 복제본은 차이가 보이도록 등급을 모두 4로 바꿨다.

| 선택 | 파일 | 충북 제보자 | 충북 호미(21105) |
|---|---|---|---|
| 2025년 | 44 | 5명 | 65.0 → `w2` 구름조금 |
| 2024년 | 5 | 5명 | 25.0 → `w4` 천둥번개 |
| 전체 | 49 | 10명 | 45.0 → `w3` 흐리고 비 (10명 평균) |
- 사용자 화면의 '단어 고르기'에는 연차 칩을 둔다. 순서는 **[전체] + 등록된 연차들**이고, 기본 선택은 **가장 최근 연차**다.
- 관리자 목록에도 연차 필터가 있고, 줄마다 연도를 보여 준다.

## 9. 화면

### 9.1 관리자 — 지역어 기상도 (`neibis-cms/mariadb/neibis/map/weather.html`)

- **탭**: 항목 목록 / 업로드
- **항목 목록**
  - 검색 조건: 조사 연차 · 자료 상태(전체 / 등급없음 / 관리자 보정) · 검색어(표준어 · 항목코드 · 지역어형)
  - 위쪽 요약: 제보자 수 · 응답 수 · 표출 항목 수
  - 칸: 지역별 `등급 행/응답 행`. 칸 색은 상태다
  - 엑셀 내려받기가 있다
- **응답 관리** (항목 하나)
  - 열 순서: 항목번호 · 일련번호 · 연도 · 지역 · 제보자 · 표준어 · 표제어형 · 방언형(기저형) · 사용도/인지도 · 판정에 쓸 값(보정)
  - 연도·지역·제보자·보정 칸은 **제보자의 첫 줄에만** 적는다. 같은 사람의 다음 줄은 비운다(의도한 동작)
  - 표제어만 있는 줄(판정에서 빠지는 줄)은 흐리게 표시한다. 방언형이 빈 줄은 '비어 있음'으로 표시한다
  - 보정 칸 선택지: `계산값 그대로 · ①~④ · 이 제보자 제외`. 옆에 계산값을 함께 보여 준다
- **업로드**: 파일 여러 개를 고르면 §4.1 사전 점검 결과를 보여 준다. 적재 뒤에는 §4.2 경고를 보여 준다
- 원자료(표제어·방언형·등급)는 화면에서 **읽기 전용**이다

### 9.2 사용자 — 지역어 기상도 (`dialect_gisangdo.html`)

- 단어 고르기(범주별 목록 + 검색 '방언형·표제어 검색') + 연차 칩
- 지도: 9개 지역에 날씨 아이콘을 표시한다. 라벨은 §5.3 표를 따른다
  - **점수는 보여 주지 않는다**
  - 지도 위에 지역별 인원 수(예: "충북 2명")도 **표시하지 않는다**
- 지역 패널: 지역별 조사된 말("표제어 · 방언형(기저형)"), 세대·성별 칸, 제보자 사례
- 범례: 맑음 · 구름조금 · 흐리고 비 · 천둥번개 · 지역어형 없음 · 관측 없음
- 상단 요약: 단어 수 · 조사 지역 수 · 제보자 수 · 조사 연도

## 10. 배포 구조와 반영 절차

```
로컬 data/gisangdo.db ──(scripts/sync_weather_turso.py --apply)──▶ Turso korean-dialect
                                                                      │  (원본 3표 통째 교체 + 미리 계산 2표)
Vercel api/index.py ◀── 읽기 ─────────────────────────────────────────┘
```

- 동기화는 **원본 표를 통째로 교체**한다. 재업로드하면 id가 모두 바뀌어서, 바뀐 것만 골라 보내는 방식이 성립하지 않는다.
- 같은 실행에서 `build_output()`으로 미리 계산까지 저장한다. 그래서 자료와 계산이 어긋날 수 없다.
- Turso 쓰기는 `turso auth login` 상태에서만 된다. Vercel에 넣은 토큰은 읽기 전용이다.
- Vercel 함수에는 `scripts/etl_awareness_region.py`와 `scripts/gisangdo_service_items.json`이 **함께 묶여야** 한다(`vercel.json` includeFiles). 빠지면 예전 기준(`all-regions`)으로 돌아간다.
- 배포 응답은 CDN에 최대 60초 캐시된다.
- 원자료 엑셀(`data/new_gisangdo/`)과 DB 파일(`data/gisangdo.db`)은 **git에 올라가지 않는다**(용량·개인정보). 개발자에게는 따로 전달해야 한다.

### 새 자료를 받았을 때 체크리스트

1. 원본 폴더를 통째로 백업한다.
2. 검사: 파일명 · 머리글 · 제보자 칸 · 남은 시트 · 등급 1~4 · 표제어 칸 하위코드 · 서비스 목록 밖 번호 · 한 제보자 안 하위코드 중복 · 수식 칸.
3. 수정 요청 엑셀로 담당자와 주고받는다. 행 번호는 **실제 엑셀 행 번호**로 적는다.
4. **빈 DB**(표 구조 + 확인된 보정만)에 44개 파일을 업로드 경로로 넣어 시험한다. 지금 DB와 지도 칸 차이를 비교한다.
5. 로컬 DB를 교체한 뒤 화면을 확인한다.
6. Turso에 동기화하고 배포 사이트 API를 확인한다.

## 13. 알려진 함정과 남은 과제

### 13.1 참고 구현에서 고친 함정과 남은 함정

새로 구현할 때도 아래 결과를 따르면 된다.

| 함정 | 처리 (2026-10-12) |
|---|---|
| **시각 기준이 섞여 있었음** — 업로드·응답의 `reg_dt`만 UTC였고(`datetime('now')`), 보정은 KST였다. 그래서 '업로드 일시'가 9시간 이르게 보였다 | **고침.** 모두 서버 로컬 시각(KST)으로 저장한다(`datetime('now','localtime')`). 이미 들어간 44개 파일·5,960행의 `reg_dt`도 +9시간 해 KST로 바꿨다 |
| **파일을 지워도 보정이 남았음** — 같은 제보자를 다시 올리면 옛 보정이 되살아났다 | **고침.** `delete`가 그 제보자의 `wb_weather_adjust`도 함께 지운다. 응답에 `adjustCleared` 건수가 들어간다. 확인창도 "보정 N건도 함께 지워집니다"로 바꿨다. 삭제 없이 **재업로드할 때는 지금처럼 보정을 유지**한다 |
| 삭제 후 "집계 재계산이 필요합니다" 문구 | **고침.** 판정은 요청마다 다시 하므로 문구를 뺐다 |
| **관리자 API에 권한 검사가 없음** — 프로토타입이라 `upload`·`adjust`·`delete`를 누구나 부를 수 있다 | **남음.** 운영 CMS에서 관리자 세션·권한으로 막아야 한다. 배포본(Vercel)은 POST를 405로 막아 둔 읽기 전용이다 |
| 시험값이 남음 — 2026-09에 기능 시험용 보정 1건이 실제 DB에 한 달간 남아 있었다 | **처리.** 2026-10-12 해제했다. 시험은 사본 DB에서 한다 |

### 13.2 데이터에 남은 과제 (지도 결과에는 영향 없음)

- **빠진 제보자 10명**: 설계 54명 중 44명이다(§11).
  - 강원·충북·전남 3명: 이번 새 서식 정리 때 빠졌다.
  - 경남 2명, 제주 5명: 예전부터 없었다.
  - 제주는 20대 남 1명이 지역 결과 전체를 대표하니, 화면이나 설명에서 이 점을 알리는 것이 좋다.
- **일련번호 불일치 160줄**: 일련번호가 `제보자+항목번호`와 맞지 않는다. 대부분 GW2550FVE에서 일련번호에 하위코드가 빠진 경우다. 판정에는 쓰지 않는다.
- **표기 예외 2줄**: '서 되'(JN2520MVE), '틀리다'(GN2520FVE). 따로 물은 줄이라 담당자 판단으로 남겼다.
- **수식 칸**: 2026-10-08 수정한 40개 파일은 수식 칸을 결과값으로 바꿔 저장했다. 이제 엑셀에서 항목번호를 고쳐도 일련번호가 따라 바뀌지 않는다.

## 14. Claude Code로 작업할 때

- 시작할 때 이 문서와 참고 구현 파일을 먼저 읽힌다.
  - 문서: `docs/gisangdo-handoff.md`
  - 판정: `scripts/etl_awareness_region.py`
  - 업로드·관리자 API: `neibis-cms/serve.py`의 `_wb_*`, `api_weather_*`
  - 사용자 화면: `dialect_gisangdo.html`
  - 관리자 화면: `neibis-cms/mariadb/neibis/map/weather.html`
  - 배포본: `api/index.py`, `scripts/sync_weather_turso.py`, `vercel.json`
- 예시 요청: "docs/gisangdo-handoff.md §5 판정 규칙을 우리 Java 서비스의 OOO 클래스에 옮겨 줘. §12 인수 기준을 단위 테스트로 만들어 통과시켜 줘."
- 지켜야 할 것:
  - 판정 규칙을 **두 곳 이상에 복사하지 말 것**. 한 모듈에서 내보내고, 관리자·사용자·배포가 모두 그 모듈을 부르게 한다.
  - 원본 응답을 고치는 기능을 만들지 말 것. 사람의 판단은 보정 표로만 한다.
  - 엑셀은 **첫 시트·결과값·NFC**로 읽을 것(§2.4).
  - 실제 DB에 시험값을 넣었으면 같은 작업 안에서 지울 것.
